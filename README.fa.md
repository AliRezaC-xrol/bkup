## معرفی و نحوه کار

bkup روی سرور خودتان و به‌صورت یک سرویس systemd اجرا می‌شود. به هر پنلی که معرفی
کنید متصل می‌شود، در بازه‌ای که تعیین می‌کنید از هر پنل یک **بکاپ کامل** می‌گیرد و
فایل را به چت یا کانال تلگرام شما می‌فرستد. مصرف منابع سرویس محدود است، در صورت
توقف خودش دوباره بالا می‌آید و پس از ریبوت سرور هم ادامه می‌دهد.

**برای هر پنل تنها یک روش بکاپ وجود دارد: بکاپ کامل خودِ پنل، بایت‌به‌بایت و بدون
هیچ تغییری:**

| پنل | آنچه گرفته می‌شود |
|---|---|
| **3x-ui** | دیتابیس کامل خود پنل (`x-ui.db`) دقیقاً همان‌طور که پنل تحویل می‌دهد |
| **HM Panel** | آرشیو رسمی و کامل پنل (`backup_full_*`) |
| **PasarGuard** | تصویری کامل از همهٔ بخش‌ها: کاربرها، هاست‌ها، نودها، کورها، گروه‌ها، تنظیمات و تمپلیت‌ها |
| **Rebecca** | خروجی کامل رسمی پنل |

bkup هیچ بکاپی را بازبسته‌بندی، فیلتر یا بازنویسی نمی‌کند و بکاپ یک پنل را به قالب
پنل دیگر تبدیل نمی‌کند. هر چه پنل تولید کرده، همان به تلگرام می‌رسد.

تنظیمات هر پنل مستقل است: هر کدام را که استفاده می‌کنید فعال می‌کنید، اعتبارنامهٔ
خودش را می‌دهید و اتصالش را با دکمهٔ تست مخصوص همان پنل بررسی می‌کنید. فاصلهٔ بکاپ
بر حسب ثانیه تعیین می‌شود؛ پس یک نصب، هم چند بکاپ در روز را پوشش می‌دهد و هم
بکاپ‌گیری در فاصله‌های چند دقیقه‌ای.

## امکانات

**بکاپ‌گیری**

- پشتیبانی از چهار پنل در یک نصب — 3x-ui، HM Panel، PasarGuard و Rebecca — با فعال‌سازی و تست جداگانه برای هر کدام
- در هر دوره، از هر پنل فعال یک بکاپ کامل و بایت‌به‌بایت گرفته می‌شود
- فاصلهٔ بکاپ بر حسب ثانیه، توسط زمان‌بند و با حفظ شدن پس از ریبوت
- ارسال هر بکاپ به‌صورت فایل در تلگرام؛ بدون هیچ دانلود دستی
- فایل‌های بزرگ‌تر از محدودیت ۵۰ مگابایتی `sendDocument` تلگرام به پارت‌های شماره‌گذاری‌شدهٔ همان فایل تقسیم می‌شوند (بخش [بازسازی پارت ها](#بازسازی-پارت-ها))
- نگهداری محلی به تفکیک پنل: نگه‌داشتن N فایل آخر هر پنل (`0` یعنی بدون محدودیت)

**پنل وب**

- داشبورد: شمارش معکوس بکاپ بعدی، کلید زمان‌بند، شمارش کل / موفق / ناموفق / ۲۴ ساعت گذشته و وضعیت اتصال هر پنل
- بکاپ‌ها: تاریخچهٔ کامل با دانلود و حذف هر فایل، به‌همراه جست‌وجوی نام فایل در ترکیب با فیلتر وضعیت
- لاگ‌ها: لاگ زندهٔ برنامه با فیلتر سطح
- سیستم: نسخهٔ نصب‌شده و آخرین ریلیز گیت‌هاب، بررسی بروزرسانی، نصب بروزرسانی، نصب مجدد، روشن / خاموش / ری‌استارت سرویس، پورت پنل و مصرف فضای دیسک
- تنظیمات: اتصال پنل‌ها، مقصد تلگرام، زمان‌بندی، فایل تنظیمات، رمز عبور و نشست‌ها

**بازسازی پارت‌ها**

- پارت‌های تقسیم‌شدهٔ تلگرام داخل خود پنل به یک فایل کامل برمی‌گردند
- امکان آپلود پارت‌ها یا انتخاب مستقیم آن‌ها از بکاپ‌های ذخیره‌شده، بدون آپلود دوباره
- مرتب‌سازی خودکار بر اساس شماره، شناسایی شماره‌های تکراری پیش از ادغام و بررسی سلامت فایل پیش از ذخیره
- گروه‌بندی پارت‌های یک فایل زیر یک سرگروه با نشان «موجود از کل» و میان‌بر **افزودن همه**
- تاریخچهٔ بازسازی با انتخاب گروهی و حذف دسته‌ای، همراه با فایل‌ها و رکوردها

**ریستور**

- انتقال یک بکاپ — معمولی یا بازسازی‌شده — روی سرور دیگر از طریق SSH
- پنل را بکاپِ انتخاب‌شده تعیین می‌کند؛ اگر پنل روی سرور مقصد نباشد، ابتدا نصب می‌شود
- قرارگیری بایت‌به‌بایت تأیید می‌شود و سلامت اجرای پنل واقعاً بررسی می‌شود
- گواهی‌نامه‌های ارجاع‌شده در دیتابیس ریستورشده، از داخل بایت‌های خود بکاپ بازسازی می‌شوند
- نمایش زندهٔ همهٔ مراحل، امکان لغو در میانهٔ کار، و تاریخچهٔ کامل با فیلتر، کپی خطا، خروجی CSV و تلاش دوباره با یک کلیک

**نگهداری**

- آپدیت درجا از پنل وب یا منوی ترمینال با حفظ کامل داده‌ها
- خروجی و ورودی فایل تنظیمات برای انتقال نصب به سرور دیگر
- تغییر رمز عبور و دکمهٔ **خروج از همه جا** برای باطل‌کردن همهٔ نشست‌ها
- حالت تاریک و نصب به‌صورت اپلیکیشن روی صفحهٔ اصلی گوشی (PWA)
- منوی ترمینال برای وضعیت، رمز، پورت، لاگ، کنترل سرویس، آپدیت و حذف

## پیش از نصب

| مورد | توضیح |
|---|---|
| سرور | دبیان یا اوبونتو با دسترسی root (نصب‌کننده سرویس systemd را در `/opt` می‌سازد) |
| رانتایم | Node.js نسخهٔ ۲۰ یا بالاتر — در صورت نبودن، نصب‌کننده خودش نصب می‌کند |
| تلگرام | توکن بات از [@BotFather](https://t.me/BotFather) و شناسهٔ چت یا کانال مقصد |
| پنل‌ها | آدرس پنل به‌همراه نام‌کاربری و رمز، یا توکن API برای حالت احراز هویت bearer |
| داکر (اختیاری) | Docker Engine با Compose، در صورت تمایل به نصب کانتینری |

## نصب

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/AliRezaC-xrol/bkup/main/install.sh)
```

نصب‌کننده این کارها را انجام می‌دهد:

1. دسترسی root را بررسی و در صورت نبودن، Node.js 20 را نصب می‌کند؛
2. **آخرین ریلیز منتشرشده** را از گیت‌هاب پیدا و دقیقاً همان تگ را دانلود می‌کند؛
3. نسخهٔ کد دانلودشده را با تگ ریلیز مقایسه می‌کند و در صورت اختلاف از نصب امتناع می‌کند؛
4. پورت پنل (بازهٔ ۱۰۰۰۰ تا ۶۵۰۰۰ یا پورت تصادفی) و رمز پنل را می‌پرسد یا رمز قوی تصادفی می‌سازد؛
5. برنامه را بیلد و سرویس systemd با نام `bkup` را ثبت می‌کند؛
6. در پایان آدرس پنل و رمز آن را چاپ می‌کند.

اجرای دوبارهٔ همین دستور روی سروری که bkup دارد، کد را درجا بروزرسانی می‌کند و
دیتابیس، بکاپ‌ها، فایل `.env` و کلیدها دست‌نخورده می‌مانند. نصب‌هایی که با سرویس
قدیمی‌تر `autobackup-xui` ساخته شده‌اند شناسایی و منتقل می‌شوند.

### داکر

فایل `docker-compose.yml` همین برنامه را به‌صورت کانتینری اجرا می‌کند:

```bash
git clone https://github.com/AliRezaC-xrol/bkup.git
cd bkup
docker compose up -d --build      # پنل وب روی http://SERVER_IP:3999
```

| تنظیم | مقدار |
|---|---|
| پورت | `3999:3000` — پنل روی پورت ۳۹۹۹ سرور در دسترس است |
| والیوم | `./data:/app/data` — دیتابیس، بکاپ‌ها و نگهداری محلی اینجا می‌مانند |
| دیتابیس | `DATABASE_URL=file:/app/data/prod.db` |
| بکاپ‌ها | `BACKUP_DIR=/app/data/backups` |
| منطقهٔ زمانی | `TZ=Asia/Tehran` |
| بررسی سلامت | `GET /api/status` داخل کانتینر |

اگر 3x-ui روی همان سرور اجرا می‌شود، خط مربوط به والیوم `/etc/x-ui:/host-xui:ro`
را در فایل compose از حالت کامنت خارج کنید تا کانتینر دسترسی فقط‌خواندنی به پوشهٔ
پنل داشته باشد.

## شروع سریع

| مرحله | کجا | کار |
|---|---|---|
| **۱** | نصب‌کننده | انتخاب پورت (یا پورت تصادفی) و رمز پنل |
| **۲** | مرورگر | باز کردن `http://<server-ip>:<port>` و ورود |
| **۳** | تنظیمات | اتصال 3x-ui، HM Panel، PasarGuard و Rebecca و زدن دکمهٔ تست هر کدام |
| **۴** | تنظیمات | وارد کردن توکن بات تلگرام و شناسهٔ چت و زدن دکمهٔ تست |
| **۵** | تنظیمات | تعیین فاصلهٔ بکاپ و روشن کردن **بکاپ خودکار** |

از این نقطه به بعد، داشبورد شمارش معکوس بکاپ بعدی را نشان می‌دهد و هر دوره در بخش
بکاپ‌ها و در لاگ زنده ثبت می‌شود.

## بازسازی پارت ها

اندپوینت رسمی `sendDocument` تلگرام در هر پیام حداکثر **۵۰ مگابایت** را می‌پذیرد.
bkup بکاپ‌های بزرگ‌تر را به‌صورت پارت‌های شماره‌گذاری‌شدهٔ *همان* فایل با نام
`<name>.part01of05.ext` می‌فرستد و دستور اتصال را در کپشن هر پارت می‌آورد:

```bash
cat my-backup.part*of*.tar.gz > my-backup.tar.gz
```

بخش **Reassemble** همین کار را داخل پنل انجام می‌دهد:

- پارت‌های دانلودشده را آپلود کنید، یا آن‌ها را مستقیم از بخش **بکاپ‌ها** انتخاب کنید؛ آپلود دوباره لازم نیست؛
- ترتیب پارت‌ها به‌صورت خودکار بر اساس شماره تعیین می‌شود و شماره‌های تکراری پیش از شروع ادغام تشخیص داده می‌شوند؛
- فایل ادغام‌شده پیش از ذخیره از نظر سلامت بررسی می‌شود و پارت‌های اصلی سر جای خودشان می‌مانند؛
- نوع پنل برای هر چهار یکپارچه‌سازی تشخیص داده می‌شود، پس هر بکاپ بازسازی‌شده از مسیر ریستور پنل خودش استفاده می‌کند؛
- پارت‌های یک فایل زیر یک سرگروه با نام فایل اصلی و نشان **موجود از کل** نمایش داده می‌شوند: سبز یعنی مجموعه کامل است و کهربایی یعنی پارتی کم است. دکمهٔ **افزودن همه** کل مجموعه را با یک لمس انتخاب می‌کند (و به **حذف** تبدیل می‌شود)، و اگر فقط یک پارت را انتخاب کنید، میان‌بر **افزودن بخش‌های جاافتاده** کنار همان هشدار ظاهر می‌شود؛
- تاریخچهٔ بازسازی یک لیست کاری است: هر سطر چک‌باکس دارد، سربرگ همه را انتخاب می‌کند و **حذف موارد انتخاب‌شده** فایل‌ها و رکوردها را با هم پاک می‌کند.

## ریستور بکاپ روی سرور

بخش **Restore** یک بکاپ را از طریق **SSH** روی سرور مقصد می‌نشاند.

سرور، پنل، تنظیمات اختیاری **Cloudflare DNS** و بکاپ را انتخاب می‌کنید و bkup پیش از
شروع، خلاصه‌ای از سرور مقصد، بکاپ و پنل را نمایش می‌دهد.

**پنل را بکاپِ انتخاب‌شده تعیین می‌کند، نه هیچ چیز دیگر.** بکاپ 3x-ui فقط روی 3x-ui
ریستور می‌شود، بکاپ HM Panel فقط روی HM Panel، و به همین ترتیب PasarGuard و
Rebecca. هیچ مهاجرت بین‌پنلی انجام نمی‌شود و بکاپ برای «سازگار شدن» بازنویسی
نمی‌شود: دقیقاً همان بایت‌هایی که پنل تولید کرده برگردانده می‌شوند، بنابراین
کاربرها، اینباندها، تنظیمات و ترافیک همان‌طور که بودند بازمی‌گردند.

اگر پنل روی سرور مقصد نصب نباشد، bkup ابتدا آن را نصب می‌کند و سپس بکاپ انتخاب‌شده
را روی آن ریستور می‌کند؛ تفاوتی ندارد پنل را شما نصب کرده باشید یا bkup.

پس از تأیید قرارگیری بایت‌به‌بایت، bkup به‌جای اعتماد به یک وضعیت ظاهری، اجرای واقعی
پنل را بررسی می‌کند: برای 3x-ui هم سرویس پنل و هم هستهٔ X-Ray کنترل می‌شوند. پیش از
راه‌اندازی پنل هم، هر فایل گواهی‌نامه‌ای که دیتابیس ریستورشده به آن اشاره می‌کند
**از داخل بایت‌های خود بکاپ** پیدا می‌شود (بدون نیاز به `sqlite3` روی سرور مقصد) و
هر کدام که روی این سرور وجود ندارد، **دقیقاً در همان مسیر ارجاع‌شده** ساخته می‌شود؛
پس اینباندی که گواهی TLS آن فقط روی سرور قبلی بوده، دیگر X-Ray را با خطای
`failed to parse certificate: no such file or directory` از کار نمی‌اندازد. محتوای
خود بکاپ هرگز ویرایش نمی‌شود.

تمام مراحل زنده نمایش داده می‌شوند، امکان لغو در میانهٔ اجرا وجود دارد و نتیجهٔ هر
ریستور در **تاریخچهٔ ریستور** ذخیره می‌شود: فیلتر بر اساس وضعیت (موفق، ناموفق،
لغوشده)، باز کردن و کپی خطای دقیق یک ریستور ناموفق، و خروجی CSV از ردیف‌های
فیلترشده. ریستور ناموفق یا لغوشده با یک کلیک قابل تلاش دوباره است — آدرس سرور،
پورت، نام‌کاربری و پنل از قبل پر می‌شوند و چون رمز و کلید هرگز ذخیره نمی‌شوند، فقط
همان اعتبارنامه را دوباره وارد می‌کنید.

## فایل تنظیمات

انتقال bkup به سرور دیگر نیازی به وارد کردن دوبارهٔ همهٔ اتصال‌ها ندارد. در
**تنظیمات**، گزینهٔ **Export settings** هر چهار اتصال پنل، مقصد تلگرام و زمان‌بندی
را در یک فایل JSON ذخیره می‌کند. اعتبارنامه‌ها به‌صورت پیش‌فرض مخفی می‌شوند تا
نگه‌داشتن و جابه‌جایی فایل بی‌خطر باشد؛ با گزینهٔ **Include credentials** مقدارهای
واقعی نوشته می‌شوند و انتقال کامل ممکن می‌شود. **Import settings** روی نصب دیگر،
فایل را با همان اعتبارسنجی فرم تنظیمات اعمال می‌کند و اعتبارنامهٔ مخفی‌شده به‌معنای
حفظ مقدار فعلی همان سرور است.

## امنیت و نشست ها

- پنل وب با رمزی محافظت می‌شود که هنگام نصب تعیین می‌شود و از پنل یا منوی ترمینال قابل تغییر است.
- تغییر رمز عبور همهٔ دستگاه‌ها را خارج می‌کند.
- **خروج از همه جا** بلافاصله همهٔ نشست‌های صادرشده را باطل می‌کند — گوشی، مرورگر محل کار و همین تب باز — بدون تغییر رمز عبور. هر دستگاه به صفحهٔ ورود برمی‌گردد و با رمز پنل وارد می‌شود.
- یک فایل کلید محلی (`.cli-secret`) به منوی ترمینال اجازه می‌دهد بدون افشای رمز با API پنل کار کند.
- نشست‌ها و دستورها در لاگ برنامه ثبت می‌شوند.

## آپدیت

| از کجا | چطور |
|---|---|
| پنل وب | **سیستم → بررسی بروزرسانی → نصب بروزرسانی** |
| پنل وب | **نصب مجدد** برای نصب دوبارهٔ همین نسخه |
| ترمینال | `bkup` → گزینهٔ **Check for updates** (۶) یا **Update** (۷) |
| هر جا | اجرای دوبارهٔ دستور نصب |

```bash
bash scripts/update.sh            # بروزرسانی با خروجی خوانا
bash scripts/update.sh --web      # حالت کم‌صدا، همان که پنل وب اجرا می‌کند
bash scripts/update.sh --force    # نصب دوبارهٔ آخرین ریلیز حتی اگر نسخه فعلی باشد
```

آپدیت همیشه آخرین ریلیز منتشرشده را پیدا می‌کند، دقیقاً همان تگ را دانلود می‌کند،
نسخهٔ کد را با آن مقایسه می‌کند و اگر تأیید نشد بدون دست زدن به نصب فعلی متوقف
می‌شود. دیتابیس، بکاپ‌ها، فایل `.env` و کلیدها حفظ می‌شوند. نسخه‌ای که پنل نشان
می‌دهد از کدِ در حال اجرا خوانده می‌شود، پس پنل هیچ‌وقت نسخه‌ای را گزارش نمی‌کند که
در حال اجرا نیست.

## منوی ترمینال

روی سرور دستور `bkup` را اجرا کنید:

| گزینه | کاربرد |
|---|---|
| **۱** | نمای وضعیت: حالت سرویس، نسخهٔ نصب‌شده، آمار بکاپ‌ها و وجود بروزرسانی |
| **۲** | نمایش آدرس و پورت پنل وب |
| **۳** | تغییر رمز پنل وب |
| **۴** | تغییر پورت پنل وب |
| **۵** | دنبال‌کردن زندهٔ لاگ سرویس |
| **۶** | بررسی بروزرسانی |
| **۷** | بروزرسانی از گیت‌هاب |
| **۸** | روشن‌کردن سرویس پنل وب |
| **۹** | خاموش‌کردن سرویس پنل وب |
| **۱۰** | ری‌استارت سرویس پنل وب |
| **۱۱** | حذف سرویس و برنامه |
| **۰** | خروج |

اگر خروجی دستور به‌جای ترمینال به یک فرایند دیگر داده شود، منو باز نمی‌شود و
فقط وضعیت چاپ می‌شود؛ همین باعث می‌شود در اسکریپت‌ها هم قابل استفاده باشد.

## حالت تاریک و نصب روی گوشی

کنار نشانگر وضعیت در هدر یک کلید روشن / تاریک قرار دارد. bkup به‌صورت پیش‌فرض از
ظاهر سیستم‌عامل پیروی می‌کند و همان کلید این انتخاب را برای هر دستگاه جداگانه
عوض می‌کند؛ انتخاب شما در بازدیدهای بعدی حفظ می‌شود. همهٔ صفحه‌ها تم می‌شوند، از
جمله کنسول لاگ و جادوگر ریستور. پالت تاریک یک گرافیتی نرم است که از مشکی و سفید
خالص فاصله می‌گیرد تا خواندن در نور کم چشم را اذیت نکند.

پنل وب یک **PWA** است: از منوی مرورگر گزینهٔ **Add to Home Screen** (در کروم
دسکتاپ **Install**) را بزنید؛ bkup در پنجرهٔ مستقل خودش با آیکون خودش باز می‌شود،
بدون نوار آدرس.

## مسیرها و متغیرها

| مسیر یا دستور | کاربرد |
|---|---|
| `/opt/bkup` | پوشهٔ برنامه |
| `/opt/bkup/.env` | پورت، آدرس دیتابیس، پوشهٔ بکاپ و منطقهٔ زمانی |
| `/opt/bkup/db/custom.db` | دیتابیس تنظیمات |
| `/opt/bkup/backups` | نسخه‌های محلی بکاپ‌ها |
| `/opt/bkup/.cli-secret` | کلید محلی مورد استفادهٔ منوی ترمینال |
| `bkup` | دستور منوی ترمینال |
| `bkup.service` | یونیت systemd (نصب‌های قدیمی‌تر `autobackup-xui.service`) |

| متغیر | کاربرد |
|---|---|
| `DATABASE_URL` | محل فایل دیتابیس تنظیمات |
| `BACKUP_DIR` | پوشهٔ بکاپ محلی (پیش‌فرض `./backups`) |
| `TZ` | منطقهٔ زمانی پنل و لاگ‌ها (پیش‌فرض `Asia/Tehran`) |
| `PORT` | پورت پنل وب |
| `GITHUB_TOKEN` | توکن اختیاری برای بررسی بروزرسانی، لازم برای ریپوی خصوصی یا سقف درخواست گیت‌هاب |

## رفع مشکلات

| نشانه | چه چیزی را بررسی کنید |
|---|---|
| پنل باز نمی‌شود | گزینهٔ ۱ منو برای وضعیت سرویس، گزینهٔ ۵ برای لاگ‌ها، و باز بودن پورت در فایروال |
| پنل نسخه‌ای قدیمی‌تر از ریلیز نشان می‌دهد | اجرای دوبارهٔ نصب‌کننده یا `bash scripts/update.sh --force` |
| بررسی بروزرسانی خطای دسترسی به گیت‌هاب می‌دهد | دسترسی اینترنت سرور و در صورت خصوصی بودن ریپو یا سقف درخواست، `GITHUB_TOKEN` یا فایل `/opt/bkup/.github-token` |
| بکاپ به تلگرام نمی‌رسد | دکمهٔ تست تلگرام در تنظیمات، توکن بات، شناسهٔ چت و دسترسی بات به نوشتن در آن چت |
| تست پنل ناموفق است ولی پنل در دسترس است | آدرس و پورت پنل، حالت احراز هویت (session یا bearer) و فعال کردن *skip TLS verify* برای گواهی‌های self-signed |
| بکاپ چندپارتی دریافت شده | بازسازی در بخش Reassemble یا اتصال با `cat name.part*of*.ext > name.ext` |
| فایل‌های بکاپ دیسک را پر می‌کنند | تعیین **نگهداری محلی** برای هر پنل (صفر یعنی بدون محدودیت) و بررسی مصرف در تب سیستم |
| رمز عبور را گم کرده‌اید | گزینهٔ ۳ منوی `bkup` روی سرور رمز را بازنشانی می‌کند |
| بعد از ری‌استارت کانتینر چیزی پاسخ نمی‌دهد | متصل و قابل‌نوشتن بودن والیوم `./data` |
